Agent 6 performs hybrid retrieval (pgvector + Postgres tsvector) over pre-ingested policy
chunks.  There is no generation prompt — this file documents the **query construction
strategy** so it can be versioned and audited alongside generation prompts (SPEC §11).

## Query construction (v1)

The embedding query string is built from the following `ExtractedClaim` fields,
concatenated in this order with single spaces between each part:

1. `denial_reason_text`  — primary signal; describes why the claim was denied
2. `"CPT: " + " ".join(cpt_codes)`  — procedure context (omitted if list is empty)
3. `"ICD-10: " + " ".join(icd10_codes)`  — diagnosis context (omitted if list is empty)
4. `"denial code " + denial_reason_code`  — CARC/RARC code if present (omitted if None)

**Example query string:**

```
Service not medically necessary per utilization review. CPT: 70553 ICD-10: G35 denial code CO-50
```

## Retrieval parameters (v1)

| Parameter | Value | Description |
|-----------|-------|-------------|
| `k_ann`   | 20    | Vector search candidates before RRF |
| `k_fts`   | 20    | Full-text search candidates before RRF |
| `top_k`   | 5     | Final results returned to caller |
| `rrf_k`   | 60    | RRF smoothing constant (standard default) |

## Fusion method

Reciprocal Rank Fusion (RRF):

```
rrf_score = 1/(rrf_k + rank_ann) + 1/(rrf_k + rank_fts)
```

Chunks that appear in only one result set receive the worst-possible rank from the
other set (`k_ann + 1` or `k_fts + 1`).  Final results are sorted by `rrf_score DESC`.

## Versioning note

Bump to `v2` if any of the following change:
- Fields used in the query string
- Order of concatenation
- Retrieval parameters (`k_ann`, `k_fts`, `top_k`, `rrf_k`)
- Fusion formula
